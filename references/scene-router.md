# 场景路由

先决定交付物，再决定布局与动效。不同场景不共用同一套信息密度。

| 场景 | 目标 | 默认结构 | 文字密度 | 点睛物 |
| --- | --- | --- | --- | --- |
| 横向教程（16:9） | 让观众跟上一个步骤或判断 | 主窗口 + 流程轨道／决策树 | 一主张、一句说明、一个机制 | 0–1 枚，必须服务步骤 |
| 演示页面（16:9） | 放大一个结论或镜头 | 单窗口 + 结论／图像／数据 | 极低 | 0–1 枚，留白优先 |
| 知识网页 | 逐段建立理解 | 主张 → 解释 → 机制 → 示例 | 中等 | 按章节出现，不做常驻贴图 |
| 落地页 | 建立兴趣与行动 | 主张 → 价值 → 证据 → 行动 | 中低 | 首屏或结尾可用一个 |
| 图文卡片／PPT | 单张截图也能被读懂 | 一个结论 + 一个图形化关系 | 极低 | 一张最多一个 |
| 组件手册 | 统一组件选择与组合 | 组件图谱 + 使用规则 | 低 | 不需要 |
| Landing / 活动页 | 建立兴趣与行动 | 不对称 Hero → 价值 → 证据 → CTA | 中低 | 首屏或收尾可用一个 |
| App / 功能展示 | 解释一个工作区或工具 | 侧栏 → 当前任务 → 状态 | 中等 | 语义光标或局部 CRT |
| 小红书图文（3:4） | 让单张卡片在手机上被读懂 | 封面 → 观点/步骤 → 证据 → 尾页 | 中低 | 封面或重点页最多一个 |
| 公众号文章 | 把原稿整理成可持续阅读的文章 | 标题 → 引言 → 章节 → 结论 → 签名 | 中等 | 章节重点处有限使用 |

## 路由问题

1. 这页要让人**理解步骤、做选择、比较差异、相信证据，还是记住结论**？
2. 观众会看多久？三秒截图、十秒视频，还是长时间网页阅读？
3. 是否真的需要 3D 物件？如果不能解释它出现的理由，就不放。

答案分别决定信息形式、文字密度与点睛物数量。
