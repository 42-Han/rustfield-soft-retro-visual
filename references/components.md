# 组件语法

完整的 52 个组件家族目录见 [component-catalog.md](component-catalog.md)。本文件保留 Rustfield 高频组件的详细结构规则；需要选低频组件时，先查目录中的格式限制与“核心／条件／静态／避免”状态。

## 先选组件类别

| 类别 | 组件 | 用来解决什么 |
| --- | --- | --- |
| 容器 | 窗口外壳、标题栏、内容面 | 给一段信息一个明确的阅读边界 |
| 标题 | 主张模块、关键词高亮、状态标签 | 让观点先于装饰被读到 |
| 关系 | 流程轨道、决策树、对比面板、数据叙事图 | 让信息之间的关系可视化 |
| 证据 | 证据放大框、引用、前后对照 | 证明或解释一个观点 |
| 点睛 | 参考文件夹、灰银 3D 金属物、选择光标、轨道环 | 指向、选择、连接或形成记忆点 |
| 动效 | 窗口进入、文字顺序出现、路径信号 | 告诉读者先看哪里、事情如何推进 |
| 单幕演示控制 | 点击或按键切换教程场景 | 让横向教程像 PPT 一样推进，而不是依赖滚动 |
| 3:4 卡片 | 固定 1080×1440 的封面、内容页和尾页 | 让单张卡片在手机上独立成立 |
| 公众号文章 | section-only、内联样式、标题断行、图片与图注 | 让原稿能复制进微信公众号编辑器 |

选择原则：**内容关系先于视觉偏好**。例如“有顺序”选流程轨道，“有选择”选决策树，而不是先选一张好看的卡片再硬塞文字。

组件手册：[组件图谱](../templates/component-atlas-16x9.html)。它用于查看和选择组件，不应直接作为普通内容页的默认布局。

组件图谱按三层组织：

- **基础视觉**：窗口外壳、标题栏、内容面、字体层级、颜色角色。
- **信息表达**：主张焦点、流程轨道、决策树、对比面板、输入输出、证据放大框、数据叙事图。
- **细节与动效**：选择光标、进度条、来源标签、局部 CRT、语义 3D 素材位与动效配方。

图谱是“选择菜单”，不是“组件清单页模板”。普通内容页通常只取一个信息组件，再从基础层和细节层各取需要的部分。

| 组件 | 作用 | 必须具备 | 不要做 |
| --- | --- | --- | --- |
| 窗口外壳 | 承载一个信息单元 | 最大窗口有灰色立体厚度；中间窗口结构清楚；小窗口保持轻量 | 把三种层级做成同一种重量 |
| 标题栏 | 标明当前内容状态 | 可选蓝、粉、灰、蓝粉渐变或灰色渐变；文字必须有足够对比 | 写成长句或塞满按钮 |
| 窗口控制组 | 强化复古窗口语法 | 最大窗口固定三个小按钮；中间窗口按完整度选用；小窗口可以省略 | 变成真实软件工具栏或挤压标题 |
| 内容面 | 提供可读区域 | 纸白底、明确内边距 | 无理由再套一个窗口 |
| 主张模块 | 让观点先被看见 | 主标题、短说明、一个符号或数字 | 放多段说明文字 |
| 主张焦点 | 放大开场或收束结论 | 一个大观点、一句辅助说明、一个克制标记 | 变成信息摘要卡片墙 |
| 流程轨道 | 展示步骤和进度 | 3–6 步、编号、一个当前步骤 | 做密集小卡矩阵 |
| 决策树 | 展示问题与分支 | 一个根问题、2–4 条清晰分支、连接线 | 让树退化成并排卡片 |
| 对比面板 | 展示选择或前后差异 | 两个并列内容面、一个明确判断维度 | 在单页塞入三种以上比较 |
| 数据叙事图 | 展示趋势或比例 | 一个图形、一处标注、一个结论 | 做仪表盘式数据堆叠 |
| 证据卡 | 展示例子或依据 | 图像／引文／对比三选一 | 把多个信息类型塞在一张卡 |
| 证据放大框 | 解释截图或案例局部 | 一张主要证据、一个框选、一个解释 | 用多张截图和密集箭头覆盖画面 |
| 来源标签 | 交代工具或语境 | 一行短文字 | 作为默认装饰反复出现 |
| 品牌标签贴纸 | 收尾时补充个人方向与记忆点 | 2–4 个独立短标签、圆角、轻微纸片层次 | 拉成横栏、塞入过多关键词、每页重复出现 |
| 点阵底图 | 增加空间与时代感 | 低对比、在窗口之外 | 盖住正文与标题 |
| 3D 物件位 | 指向、解释或形成记忆点 | 一个具有内容语义、材质明确的物件；可选星体、光标、轨道环、心形吊饰或回形针 | 使用抽象色球或同屏出现多个互相竞争的物件 |
| 银灰符号点缀 | 指向主张、标记证据或连接步骤 | 箭头、星标、光标与内容有明确关系；每幕最多少量 | 孤立球体、轨道环、平面渐变贴纸、抠图白底或无理由堆满 |

## 细节组件的使用边界

- **选择光标**：只指向一个需要看的位置；不作为每页的品牌贴纸。
- **进度条**：只表达处理中、加载或推进状态；不把它重复成装饰线。
- **来源标签**：只在来源、工具、版本或语境需要交代时出现。
- **品牌标签贴纸**：只在个人品牌收尾或需要快速建立身份时出现。每个标签单独成形，使用圆角胶囊、细边界、低强度内高光和很轻的环境影；可有极小的圆点或轻微角度差异来模拟贴纸，但不能变成厚重按钮、全宽横栏或密集关键词墙。
- **局部 CRT**：只覆盖素材屏幕、对比框或转场层；不进入主要正文。
- **语义 3D 素材位**：先决定它承担“转折、选择、连接、反应”中的哪一种，再选择真实素材；没有透明、光向和阴影控制时宁可不用。
- **银灰符号点缀**：箭头必须指向一个主张或当前路径，星标必须标记一个证据或记忆点，光标必须连接一个动作。使用灰银单色、统一高光方向和低振幅动效；如果无法说清它指向什么，就不要放。
- **手册素材优先**：需要参考文件夹、银灰星体或光标时，优先直接复用 `assets/reference-folder-alpha.png`、`assets/silver-metal-star-alpha.png` 与 `assets/chrome-cursor-alpha.png`；它们已经处理好透明边缘、体积、高光与阴影，不要重新用 SVG 或渐变色块仿制。
- **动效**：每页最多一个主动作，连续漂浮只给有语义的小物件，且必须支持静态阅读。
- **单幕演示控制**：播放页只呈现一个当前场景；点击场景或使用方向键／空格键切换。保留静态可读兜底，避免把所有场景压在同一张滚动长页里；除非确实需要进度信息，否则不添加底部控制栏。
- **窗口控制组**：最大层级标题栏右侧固定放置最小化、最大化、关闭三个灰色小按钮；中间窗口可以保留完整控制组，小窗口可以省略。按钮承担视觉结构，不额外塞入复杂交互。
- **按钮外观**：除浅色描边与透明按钮外，允许使用纯信号粉底白字、纯编辑蓝底白字的无描边按钮；实色按钮只保留给需要被优先看到的真实动作。
- **关系连接轨道**：流程、输入输出和教程步骤必须把连接线放在节点之间的独立布局轨道里。轨道随节点宽度自适应，箭头终点停在下一节点边缘，禁止使用覆盖内容的固定坐标 SVG。
- **结构化决策树**：使用根节点、主干、水平分叉、分支竖线和结果节点五层结构。连接关系由布局生成；窄屏时保留根到分支的顺序并改为纵向，不把路径压成错位卡片。

## 3:4 与公众号组件

- **3:4 卡片封面**：一个主标题、一句副标题、作者识别和可选灰色窗口；内容不能被装饰物遮挡。
- **3:4 编号页**：大淡色编号作为空气层，标题和正文必须先于编号被读到。
- **3:4 证据页**：一张大图 + 一个框选 + 一句解释；图片与解释之间保留明确间距。
- **3:4 尾页签名**：黑猫头像、`@锈原 Rustfield`、一句简介和 2–4 个独立圆角标签。
- **公众号章节头**：英文短装饰词 + 中文标题 + 粉色重点条；复制版必须全部内联。
- **公众号引言**：浅粉或雾蓝纸面，正文 18px、行高约 2；不使用默认 blockquote。
- **公众号图片**：预览版可用相对路径，复制版支持 base64；图注独立、短、低对比。
- **公众号高亮**：使用粉色荧光笔底纹，每节 1–3 处，不把整段文字涂满。

## 证据与图表的分层规则

- **证据放大框**：证据本体、局部框选、解释文字是三层。证据本体不被解释文字压住；解释文字必须完整在证据外，或完整置于一个独立标注框内。
- **数据叙事图**：网格与坐标是结构层，面积是背景层，趋势线是数据层，粉色点位是结论层。不要用深色实心几何块表达数据。
- **关系图**：边和箭头先于节点外观；如果连接关系不清楚，不能靠增加阴影、圆角或颜色补救。

## 窗口外壳结构

```text
灰色立体外框
  └─ 内嵌蓝色标题栏
      └─ 纸白内容面
      └─ 一个主要内容机制
```

窗口外壳只是一层容器。内容面里的卡片应是平面信息块，而不是缩小的第二套操作系统。
