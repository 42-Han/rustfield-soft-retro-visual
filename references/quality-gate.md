# 交付前质量检查

## P0：必须通过

- 三秒内是否能读到主标题？
- 三秒内是否能判断这页是在讲流程、对比、引用还是演示？
- 是否只有一个主观点／主操作？
- 灰色是否只用于窗口外壳，主窗口是否为“灰色立体外框 + 内嵌蓝色标题栏”？
- 粉色是否只承担重点、当前状态或标记，而不是成为大面积底色？
- 深蓝是否只留给主标题栏和一个当前状态，而非填满多个次级模块？
- 主窗口是否使用明确结构影；次级窗口若需要机身感，是否使用低饱和蓝/粉环境影和内高光，而非把硬灰投影复制到每张卡片？
- 主体是否避开了默认霓虹、赛博控制台、无意义光效与密集小字？
- 所有 3D 物件是否有语义、透明边缘干净、阴影方向一致？
- 箭头、星标或银灰点缀是否真的指向主张、证据或路径？孤立球体、轨道环和无指向装饰是否已经删除？
- 如果使用参考文件夹、银灰星体或光标，是否优先复用了手册透明素材，而不是重新绘制一个平面替代品？
- 数据叙事页是否只使用一种图形、一个关键标注和一句结论，而不是堆叠成仪表盘？

## P1：应当通过

- 是否只有一个主要窗口和一个主要内容机制？
- 横向教程播放页是否默认只显示一个场景，并能通过点击或方向键推进，而不是要求连续滚动或依赖底部控制栏？
- 最大层级场景窗口是否保留了统一的最小化、最大化、关闭三枚控制符？中间和小窗口是否按层级减轻，而不是全部复制同一套标题栏？
- 是否已经删去不承担信息的标签、按钮和嵌套卡片？
- 如果使用品牌标签贴纸，是否为 2–4 个独立的圆角标签，并且没有连成横栏、遮挡正文或变成关键词墙？
- 流程是否有方向、连接与当前状态，而不是退化为表格？树状内容是否使用分支结构，而不是横排卡片？
- 流程和输入输出的箭头是否位于独立连接轨道中，并在不同宽度下都停在节点边缘？
- 决策树是否具有清楚的根、主干、水平分叉和各自分支线，而不是依赖固定坐标覆盖层？
- 蓝粉渐变是否经过低饱和中间色自然过渡，没有形成左右两块硬切色？
- 最大窗口是否保持轻度机身感而非厚重相框感，并与层级示例共用同一套窗口 Token？
- 横向视频中的标题、正文、标签是否符合 64–76px、24–30px、16–18px 的层级？
- 中文标题是否有舒适的行高和字距，笔画没有互相挤压，辅助文字是否与标题形成清晰层级？
- 画面是否有足够呼吸感，图片组、文字组和点睛物是否分布在明确区域，而不是全部挤在中心？
- 在窄窗口和大屏浏览器中，标题是否保持同一视觉尺度，且只有内容设计的换行，而不是视口放大造成的换行？
- 点阵、CRT 和动效是否避开正文？
- 静态截图是否仍然完整可读？
- 漂浮／弹跳是否低振幅、低频率、不会抢走标题？
- 证据页是否只有一个主要证据和一个局部解释，截图本身是否仍然清楚？
- 动效是否只服务于进入、推进、聚焦、变化或气氛中的一个关系？
- 连续漂浮／旋转是否只用于有语义的物件，并且没有遮挡标题、正文和关键路径？
- 是否在 `prefers-reduced-motion` 下保留最终可读状态？
- 3:4 小红书卡片是否严格以 1080×1440 为设计基准，导出时没有把页面截图成错误比例？
- 3:4 卡片是否按“封面／观点／步骤／证据／收束”组织，每张只完成一个阅读动作，并且最多保留一个主机制？
- 公众号文章是否使用 677px 左右的阅读宽度、足够大的正文行高和可直接粘贴的 section 结构？
- 公众号输出是否去掉了窗口外壳、脚本说明、交互控件、外链依赖和复杂 class 结构？
- Landing 是否只有一个主行动，App 是否能一眼区分导航、当前状态、工作区和任务？
- Landing 的身份标签是否轻量、透明或印章化，并且没有抢走主标题？
- Landing 的三项价值是否通过节点、线或明显的顺序关系组织，而不是三个同重的呆板矩形卡片？
- App 的侧栏是否只承担导航，当前任务是否成为主视觉，证据图是否完整可见且没有被裁切？

## P2：加分但不强制

- 配色是否有限且角色明确？
- 留白、间距和线条是否一致？
- 是否有一个与内容有关、而不是纯装饰的记忆点？
- 如果删掉一半装饰会更好，是否已经删掉？
