# 场景规范：App 型与功能展示页（16:9 / HTML）

## 目标

把工具、工作流、知识库或内容产品展示成一个有结构的工作区，而不是通用 AI 控制台。

## 页面结构

```text
一个灰色主窗口
  └─ 蓝色标题栏 + 三枚窗口控制
      ├─ 轻量侧栏：导航或章节
      ├─ 主工作区：一个当前任务
      └─ 状态区：当前进度、来源或下一步
```

## 组件边界

- 侧栏只放 3–6 个导航项；当前项用粉色，不用整栏深蓝。
- 主工作区只保留一个当前任务或一组同级信息。
- 信息层级固定为：工作区标题 > 当前任务标题 > 解释正文 > 下一步提示 > 状态栏；不要让状态、说明和图片拥有同样的视觉重量。
- 证据图使用 `object-fit: contain` 完整展示，图片框可以变大，但不能通过裁切来填满空间；图片应该成为任务的主要证据，而不是右下角缩略图。
- 侧栏采用 Y2K 的“章节编号 + 当前状态 + 轻量几何线索”表达，不用深蓝整栏，也不把三个导航项做成同样重的按钮。
- Tab、Modal 和 Accordion 只能在 HTML 预览中启用；截图和公众号输出要呈现静态最终状态。
- 若使用 Canvas，连接线要先于节点样式，节点数量要少且有解释。

## 禁忌

- 不做 KPI 卡片墙、密集数据仪表盘或深蓝填满的 SaaS 首页。
- 不把真实软件操作按钮伪装成装饰物。
- 不把关键参考图缩成小方块；如果证据图看不清，优先扩大图片区或拆成下一幕。
